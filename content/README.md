# 内容维护

使用 Node.js 22，首次执行 `npm ci`。修改内容后执行 `npm run check:content`、`npm run build`、`npm test`。构建自动扫描作品、作者和专题，无需在程序中登记文件。

| 位置 | 用途 |
| --- | --- |
| `works/<朝代>/*.md` | 一篇作品一个文件，按先秦、汉、三国、晋、南北朝、唐、五代、宋、元、明、清归档；其他朝代可直接建目录，年代不明用 unknown |
| `authors/*.md` | 一位作者一个文件，作品以作者 ID 引用 |
| `taxonomy.yaml` | 多级标签；parent 引用父分类，顶级为 null |
| `topics/*.yaml` | 专题及作品 ID 列表；works 列表控制专题内顺序 |
| `modules.yaml` | 模块显示名称、顺序和默认可见性 |
| `discovery.yaml` | 默认作品、首页意象入口、发现页风景、心境与地名入口 |
| `site.yaml` | 内容格式版本和名称 |
| `games/mystery/lotus-letter.json` | 荷塘来信的章节、信件、逐层提示与作品引用 |
| `games/feihua/settings.json` | 飞花令的令字、场景名与一场的往来次数 |

目录仅用于归档。每篇作品只存一份，通过多个标签进入不同分类。文件可移动或改名，已发布的 `id` 应保持稳定，收藏、专题及关联阅读依靠它识别作品。作者文件里的朝代是展示依据，移动目录不会自动改动文学信息。

## 维护作品

复制 [静夜思](works/tang/jingyesi.md) 等相近作品，修改文件头和正文，存入相应朝代目录。使用 UTF-8，YAML 缩进采用空格。ID 以小写字母开头，仅含小写字母、数字、下划线和连字符。

```markdown
---
id: new-work
title: 篇名
author: libai
form: 五言绝句
stage: []
tags: [moon]
scene: moon
quote: [0, 1]
intro: 一句话引导。
related: []
---

## 原文 {#lines}

第一句，
第二句。

## 写作缘起 {#background}

背景文字。
```

- `author`、`tags`、`related[].id` 必须引用已有条目；新增作者先创建作者文件。
- `stage` 可留空，或填写小学、初中、高中，不决定主要导航。
- 正式作品应补齐作者或文献来源简介、字词、背景、具体引文的赏读、心意与可对照的出处；节选需注明首尾范围，存在异文和署名争议时分别说明。`sources` 中的 HTTP(S) 网址会显示为可打开的资料链接。
- `quote` 是默认选句，**从 0 开始计数**，忽略原文空行。调整分行后检查选句；已收藏摘句及诗卡保留当时的文字快照。
- `order` 可选，数字小的优先；未填写排在后面，同序按 ID 排列。
- `scene` 支持 moon、mountain、water、rain、snow、bamboo、flower。
- 标题中的 `{#lines}` 等是固定标识，中文标题可以改名。原文每个非空物理行是一句或一段，可点击查看释义。

| 模块标识 | 编写规则 |
| --- | --- |
| lines | 必需；原文逐行书写 |
| preface | 可选序文 |
| notes | 三级标题 `### 词语`，下方写解释；每个词语独立一条 |
| background | 背景段落 |
| reading | `### 赏读标题`，接 `> 引文`，再写讲解；多条重复此格式 |
| thought | 思想与情感 |
| sources | 出处列表，每条以 `- ` 开始 |
| places | 字里的山河；古今地名、关联方式与必要的地望辨析，段落间留空行 |

除原文外的模块可省略。结构化 Markdown 支持上述标题、段落、引文和列表约定；正文安全地按文本显示，不执行 HTML，也不解析任意 Markdown 扩展。

## 扩展与删除

古今地名沿用标签体系：`geography` → 今天的地区／历史区域／地望辨析／想象天地 → 地点。作品的 `tags` 引用地点 ID，同时在 `## 字里的山河 {#places}` 写清古称、今地与关联方式（正文、写作背景、目的地、回忆、典故或想象），依据列入本篇 `sources`。不凭作者籍贯推定作品地点；范围、同名异地或地望有争议时明确说明。真实地点只按较可靠的区域归类，争议地点不强行归到某个省市。

`discovery.yaml` 的可选 `places` 列表控制地名推荐卡片，格式与 `landscape` 相同。搜索支持地名说明和标签上级地区名。地名之间任选其一，与风景、情感等不同类别组合时取交集。页面内可通过模块和分类设置修改，导出的内容包、个人备份和独立 HTML 会携带这些资料。

新增分类后，将 ID 加入作品 `tags` 即可；是否放到醒目的入口由 `discovery.yaml` 决定。新增普通文本模块时，在 `modules.yaml` 增加 `{id: place, label: 一处地名, enabled: true}`，再在作品中写 `## 一处地名 {#place}` 和正文，空内容不显示。新的交互类型需要开发对应组件。

“游园 · 拾句成诗”自动从当前作品的原文提取相邻的五言、七言诗句，不另存一份题库。选句要求前句以逗号结束、后句以句号或问号、叹号结束，两句字数相同；古文、词、曲不参与。五言按 2＋3、七言按 2＋2＋3 切分为游戏碎片，这只是玩法切分，不表示唯一的语义或朗读停顿。维护或导入原文后自动重新选句；没有适合的作品时显示阅读入口。

“诗境解谜 · 荷塘来信”使用 `games/mystery/lotus-letter.json`。章节标题、场景文字、来信、分层提示与作品引用在这里维护；机关规则、插画生成、动效与界面在 `src/games/mystery/` 分别维护，池塘的分层插画为 `src/art/mystery/pond.svg`。增加不同机关的章节需要对应交互实现。

作品引用包含 `workId`、`authorId`、从 0 开始的两行 `lines`，`expected` 保存经人工核对的引文。展示时从当前作品取原文与作者信息。修改引用原文后，构建会要求重新审阅图义并更新校核值。

章节、插画与动效一起打包进独立 HTML；导出的阅读文件不携带个人游戏进度。进度使用 `shanyue.mystery.v1` 存储，在个人备份的可选 `games.mystery` 字段中迁移，兼容不含此字段的旧备份。章节配置随网站维护，不进入个人内容补丁。当前作品缺失、引文或作者不一致时，章节暂停展示，其他阅读与游戏仍可使用。修改后运行 `npm run build` 和 `npm test`。

“飞花令 · 和山月接诗”从当前作品库提取包含令字的五言、七言短句，限定五言／七言诗、乐府与歌行等诗体，不纳入古文、词曲。全文与作者仍以作品文件为准，双方已用的同文句子在本场去重，回复优先换作者、换作品。未匹配的输入不直接判错。令字需为一个汉字，配置的每字至少有两句可用原诗；内容导入后不足的令字暂不展示。

玩法配置位于 `games/feihua/settings.json`；纯规则、SVG 插画、样式与视图位于 `src/games/feihua/`。进度以 `shanyue.feihua.v1` 保存，一次送出同时保存双方诗句，界面随后播放往来动效。个人备份使用可选 `games.feihua` 字段；旧备份不影响现有进度，内容包不携带进度。已用原文或作者引用发生变化时，提示重新开场；标题与作者姓名修订可采用当前内容。独立 HTML 包含完整玩法，不携带他人的个人游戏记录。

“荷塘来信 · 借水行舟”使用 `games/voyage/chapter.json` 管理两岸名称、邀请、引文和对应作品；引用包含 `work`、`author`、从 0 开始的 `lines` 和审阅值 `expected`。规则、插画、动效与界面分别位于 `src/games/voyage/`。构建时校核引文；个人内容修改使引用失效时，仅关闭对应水道。新增场景或机关需实现对应图形与规则，不是只增一条配置。

借水行舟以 `shanyue.voyage.v1` 保存当前水道、最近操作和已发现的路线方式，个人备份使用可选 `games.voyage` 字段。动作先保存目的状态再播放动效，刷新或中途离开不会丢失已完成选择。独立 HTML 内嵌完整玩法，不携带个人进度；诗笺从实际场景生成。

删除作品前，移除其他作品的 related、专题 works、默认作品及游戏场景中的引用；删除作者和分类同样需要处理引用。校验会报告遗漏，避免发布失效链接。

## 发布与个人修改

生成的 `index.html`、`offline.html` 不直接编辑。源文件拆分后，构建仍会把完整内容打包进页面，保留单文件离线能力。

网页内编辑只影响当前浏览器。正式内容通过提交文件和发布更新。个人备份采用版本 2，兼容导入版本 1 的旧备份；内容包继续使用版本 1。未修改的内置字段随网站更新，个人修改优先保留；冲突可在“阅读与内容设置”中查看并选择采用新版。

旧浏览器数据迁入新存储项，原 `shanyue.reading.v1` 留作迁移备份。`src/data/legacy-v1-fingerprints.json` 是识别旧版原始内容的冻结指纹，不是第二份内容来源，不应随内容修改重新生成。

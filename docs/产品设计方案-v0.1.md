## 2. 产品要解决的三个问题

1. 找得到：既能按年级、教材册次查篇目，也能从情感、景物、作者、手法等入口找到关联作品。
2. 看得懂：原文与注释、作者经历、背景、手法、思想之间能相互索引，讲解深度适合当前学段。
3. 记得住：阅读后可做理解和背诵练习，按自己的掌握情况安排再次复习。

典型使用场景：学生复习本册要求背诵的作品；家长按“月与思念”组织一次专题共读；学生读完《静夜思》后延伸阅读同一作者或相近主题的优秀作品。

## 3. 收录范围与可信依据

### 3.1 内容范围

收录古诗、词、曲、古文、辞赋。教材中的节选、组诗、组文分别记录实际学习范围。小学中的短篇文言文同样属于目录范围，不能只整理古诗词。

三个来源入口可以重叠：

| 入口 | 内容 | 展示规则 |
| --- | --- | --- |
| 教材收录 | 经核对的教材正文、古诗词诵读、语文园地等栏目中的古诗文 | 标出学段、年级或课程模块、册次、单元、教材版本 |
| 课程要求 | 适用课程标准中的推荐篇目及具体要求 | 标出文件、版本、适用学段及要求原意 |
| 拓展阅读 | 教材范围外有阅读价值的优秀作品，以及相关完整篇章 | 标出推荐理由和建议阅读学段，避免标成教材必背 |

“教材收录”“课标推荐”“要求背诵”不是同一件事，分别记录。一篇作品可以同时具有多种来源。背诵必须记录全文或指定段落，不能因作品被教材收录就默认全文必背。

初步以 2026—2027 学年作为教材适用信息核查基准；最终以实际查到的有效材料为准。对不同年级的修订版、过渡版本分别映射，不假定全国所有学生使用完全相同的册次和篇目。

### 3.2 来源核查方法

实施时按以下来源逐项建立证据：

1. 教育部发布的适用课程标准与教材相关文件，确定课程范围与要求。
2. 出版社或官方教材平台提供的对应版次教材目录、正文和学习指令，确认收录、文本与背诵范围。
3. 若以后启用地区或考试专题，再核查对应年份、地区的官方材料。
4. 原文校勘、作者与创作背景使用可信古籍整理本、权威出版资料等；现代译注和赏析自行组织表达，并保留参考来源。

每个来源记录名称、发布或出版单位、版本或日期、页码或章节、可用链接、核验日期。教材收录事实、背诵要求、背景事实和赏析判断各自挂接相应来源。

背景或年代有争议时写明“说法之一”“时间未详”等；作者归属不确定、集体创作、佚名等按真实情况记录，不为补齐字段而编造。

### 3.3 当前项目资料的使用方式

现有 `base/base-note.md` 是候选篇目和标签草稿，尚不能作为已核定的全国现行教材目录。

已发现的结构与示例问题：

- “小学 75 首、初中 61 篇、高中 34 篇”的数量标签缺少版本和来源链，且小学部分混有“拓展”条目，不能据此宣称范围完整。
- “派别”中混有朝代、诗人、文学流派和艺术风格；部分作者的词风被套用到诗作。
- 《鹿柴》的“月”标签、《风》的“雪”标签缺乏对应原文依据。

后续将逐条校核、去重、补充来源和重新分类，再统计“独立作品数”“教材收录次数”“学习节选数”。本轮未进行官方来源的在线全面核验，不给出确定篇目总数。

## 4. 信息组织：目录与多维分类

### 4.1 教材目录

基本路径为：学段 → 年级或高中课程模块 → 册次 → 单元或栏目 → 作品。

全站每篇作品有稳定标识；同一作品在不同教材、学段或专题中出现时，均指向同一作品主体，再选择对应文本版本与节选范围。标题相同的不同作品用作者、首句、组诗序号等区分。

章节和节选保留层次关系，例如组诗 → 其一，完整古文 → 教材节选。整篇未收录部分不计入该册的要求背诵范围。

### 4.2 多维、多级分类

每个维度内部采用层级分类，一篇作品可以关联多个维度和多个标签。避免把所有作品强行塞进一棵互斥的分类树。通常展示二至三级，数据结构允许进一步扩展。

| 维度 | 层级示例 | 分类说明 |
| --- | --- | --- |
| 情感 | 思念 → 思乡／怀人／思亲；家国 → 忧国／忧民／报国；人生 → 孤独／失意／旷达／珍惜时光 | 可标主要与次要情感，必要时注明段落中的变化 |
| 题材 | 羁旅 → 客居／行役；送别 → 赠友／送亲；山水田园 → 山水／农事；怀古咏史；咏物言志；边塞；节令民俗；劝学修身 | 题材与情感分别维护，例如“送别”可以表达依依不舍，也可以表达劝勉 |
| 景物与意象 | 天象气象 → 风／雨／雪／霜／露／云／月／日／星；山川水域 → 山／江／河／湖／海／溪／瀑；植物 → 花 → 梅／兰／荷／菊／桃；植物 → 树木 → 柳／松／柏；动物 → 雁／燕／鹤／蝉；人文景物 → 楼台／城关／舟／桥／驿路 | 既可按“风、花、雪、月、山”直接进入，也可向上汇总或向下细分 |
| 时空 | 季节 → 春／夏／秋／冬；时段 → 清晨／白昼／黄昏／夜晚；节日 → 清明／端午／中秋／重阳；地点 → 地理区域／具体地点 | 地点区分作者籍贯、写作地与作品描写地 |
| 文学流派 | 诗歌 → 山水田园诗派／边塞诗派／江西诗派；词 → 豪放派／婉约派；散文 → 桐城派等 | 仅在依据明确且适用时标注，允许不归入特定流派 |
| 艺术风格 | 清新自然／雄浑豪放／沉郁顿挫／婉丽含蓄／浪漫奇崛等 | 与流派分开，作者总体风格不能直接替代单篇判断 |
| 体裁 | 诗 → 古体诗／近体诗 → 律诗／绝句；词；曲；古文 → 记／说／论／序／表／书；辞赋 | 文体与格律信息分层保存 |
| 表达手法 | 修辞 → 比喻／拟人／夸张／对偶／用典；表现 → 托物言志／情景交融／虚实结合／动静结合／对比衬托；结构 → 起承转合／首尾照应等 | 每个具体分析应能指向原句、段落及表达效果 |
| 作者与时代 | 朝代或时期 → 作者 → 作品 | 诗集、总集、佚名、民歌另设合适的署名与出处方式 |

“风雅”之“风”与气象“风”是不同概念，搜索可命中同字，但分类不合并。树枝下无作品的分类可隐藏；未归类的作品仍可通过教材目录、作者或搜索访问。

### 4.3 标签的证据与筛选规则

- 作品级与诗句、段落级标签同时支持。点击标签能查看相关原句及简短解释。
- 景物区分实写、想象、回忆、比喻、典故等出现方式，不仅做字面关键词匹配。
- 不把“月”等意象固定解释为某一种情感，始终结合该篇文本和语境。
- 同一维度内多选默认“任一符合”，不同维度之间默认“同时符合”。需要时可在同一维度切换“全部符合”。
- 选择父分类包含其子分类；结果按作品去重，界面显示当前条件和结果数。
- 搜索覆盖题名、别名、首句、原文、作者、标签；返回命中片段，帮助辨认同题作品。

示例：选择“初中 + 思乡 + 月”，获得同时满足三个条件的作品；选择“花”会包含“梅、荷、菊”等子类。

《静夜思》的示例分类：唐 → 李白；情感 → 思念 → 思乡；景物 → 天象 → 月；景物 → 气象 → 霜（比喻中的景象，证据为“疑是地上霜”）。以上仅示范分类方法，教材册次和版本另行核查。

## 5. 作品详情与内容模块

原文、署名或出处、版本与来源是作品的基础资料。讲解内容采用可配置模块；模块可启停、排序、新增和设定适用学段。模块不适用或尚无内容时，不用空面板占据学习页面。

| 模块 | 内容 | 默认使用方式 |
| --- | --- | --- |
| 原文 | 保留诗行、段落、序文与教材节选边界；必要时查看异文 | 默认显示；练习时可按范围遮盖 |
| 注音与朗读提示 | 生僻字、多音字、古音读法与节奏提示 | 小学优先；只展示经过核对的读音 |
| 字词与译意 | 重点字词、逐句释义、文言句式与段落大意 | 点击原句关联查看，按学段控制深度 |
| 作者简介 | 生卒年、时代、重要经历、代表作、与本篇有关的经历 | 卡片先给短简介，详细生平按需展开；人物资料复用 |
| 创作背景 | 时间、地点、历史处境、写作缘由、出处及争议 | 重点解释理解本篇所必需的信息 |
| 核心思想与情感 | 一句话主旨、层次说明、情感变化、原文依据 | 首屏简述，随后可展开 |
| 创作手法 | 手法名称、对应诗句、具体表达效果 | 使用“原句—手法—作用”的结构 |
| 景物与意象 | 景物位置、出现方式、在本篇中的作用 | 与分类标签和原文联动 |
| 结构与脉络 | 起承转合、叙事线索、论证结构、段意 | 长篇古文优先提供 |
| 背诵与易错点 | 指定背诵范围、分段线索、易错字、易混句 | 背诵模式使用 |
| 理解问题 | 经过编写和审核的问题、参考要点、原文依据 | 形成理解练习卡，不自动把赏析拆成固定唯一答案 |
| 关联阅读 | 同作者、同情感、同意象、同题材、同手法的作品 | 推荐要说明关联理由，教材外作品标为拓展 |
| 学习要求与来源 | 收录位置、推荐或背诵要求、出处、核验信息 | 可随时查看，避免打断常规阅读 |
| 自定义模块 | 比较阅读、家长提示、名句积累等 | 可选择文本、条目、问答、诗句解析或关联作品类型 |

预设“小学、初中、高中”三套模块显示方案，允许调整，不限制学生主动查看深入内容。小学侧重读音、画面、浅显译意和简短情感；初中增加文言基础、意象与手法；高中增加结构、论证、深层背景及比较赏析。

## 6. 卡片交互与学习闭环

### 6.1 两类卡片

**作品卡**服务于发现和阅读：题名、作者、学段或来源、原文预览、少量主要标签、学习状态。进入后查看完整详情；长篇按段落阅读，不把整篇古文压缩到固定高度卡片中。

**练习卡**服务于回忆和巩固：正面是一个明确任务，背面是答案或参考要点及出处。支持“看答案”“查看相关原文”“上一张／下一张”和掌握情况自评。长讲解使用展开详情，不依赖整张卡的三维翻转。

### 6.2 三种学习模式

| 模式 | 操作 | 结果 |
| --- | --- | --- |
| 阅读理解 | 看原文 → 按需展开词义、背景、手法 → 查看关联作品 | 记录阅读位置，不直接认定已掌握 |
| 理解练习 | 看问题 → 自己作答或口头表达 → 显示参考要点和原文依据 | 自评“需再学／基本理解／能说明白” |
| 背诵练习 | 选择范围 → 按句或段遮盖 → 回忆 → 显示答案核对 | 自评“不会／不熟／熟练”，记录到该背诵范围 |

短诗可整首练习；长篇先按教材规定段落或用户选定片段练习。显示答案按钮始终可见，滑动手势可作为辅助，但不能成为唯一操作方式。

### 6.3 流程与复习

```mermaid
flowchart LR
    A[按教材、主题或搜索选作品] --> B[阅读作品卡与详解]
    B --> C[选择理解或背诵练习]
    C --> D[显示答案并自评]
    D --> E[记录掌握情况与下次复习]
    E --> F[继续学习或结束本次]
    F --> A
```

学习卡组可由一本教材、一个分类筛选结果或个人收藏生成；区分固定收藏与随内容更新的筛选卡组。本次学习开始后固定队列，中途新增内容不打乱当前进度。

首版提供简单、透明的复习安排，例如“不会”进入本次稍后重试，“不熟”建议次日再看，“熟练”延长间隔。最终间隔可配置；这属于复习提醒，不宣称系统能够自动判断记忆效果。

理解状态与背诵状态分别保存。练习进度关联作品、文本版本、学习片段与任务类型；修改原文或节选后提示重新确认相关进度。完成阅读、点开答案和用户自评属于不同事件。

没有理解题的作品仍可阅读及背诵；筛选无结果时展示当前条件并支持逐项移除；本次中断后可继续；误标掌握状态可撤销。

## 7. 页面结构与移动端设计

建议提供“目录、专题、学习、我的”四个主入口。作品详情是共享页面；设置和管理从“我的”进入。

| 页面 | 主要内容 | 手机端安排 |
| --- | --- | --- |
| 目录 | 学段、教材、册次、来源筛选、搜索、作品列表 | 先展示当前范围；深层条件集中在筛选面板 |
| 专题 | 情感、景物、题材、流派、手法等分类及相关作品 | 分类逐级进入，并显示面包屑与作品数 |
| 作品详情 | 原文、模块导航、相关解析、学习入口 | 单列阅读；点击诗句展开关联注释；返回保留原筛选和滚动位置 |
| 学习 | 本次卡组、复习任务、理解或背诵练习 | 单卡聚焦；主要操作靠近下方；长文可自然滚动 |
| 我的 | 收藏、学习记录、显示偏好、配置与备份 | 常用设置在前，内容管理单独进入 |

视觉方向建议为简洁书卷风：浅暖底色、深色正文、少量青绿或朱红强调。原文可使用系统宋体类字体，控制和说明使用易读字体，不依赖在线字体或背景插画。

移动端优先，覆盖 320px 起的窄屏；正文建议 18–22px 可调，段落留出朗读空间，触控目标约 44px。长诗句可以换行并保留诗行分组；古文按段落排版。电脑端可采用左侧目录、右侧内容或列表与详情并列。

支持键盘操作、可见焦点和减少动画；类别和掌握状态同时用文字表达，不能只靠颜色。字体放大后不应遮挡练习按钮。浏览器返回能正确返回列表、详情和学习会话。

## 8. 轻量配置与内容维护

### 8.1 页面内配置

- 分类管理：新增、重命名、调整顺序和父子关系、停用或删除分类，修改作品与标签的关联。
- 模块管理：新增、改名、排序、启用或停用模块；选择模块类型；设置学段预设及默认展开状态。
- 显示设置：字号、阅读配色、默认学段、学习模式和复习间隔。
- 内容更新：导入新增或更新的作品内容包，检查后合并；支持隐藏作品及撤销。

首版定位为轻量配置。分类和模块可在页面内操作；大批原文、译注和详解的维护以结构化内容包导入为主。复杂的逐篇富文本编辑、多人审核和在线内容后台属于后续能力。

新增模块只会增加内容结构，不会自动生成每篇作品的讲解。空模块默认隐藏；具体内容可通过导入补充。基本身份信息、文本来源和内部关联字段不作为可删除的普通模块。

### 8.2 删除、导入与备份规则

分类删除前展示影响篇数，并选择将关联迁移到其他分类、解除关联或取消；不连带删除作品。模块优先停用，彻底删除时明确数据影响并支持导出备份。分类移动不得形成循环父子关系。

导入前展示新增、更新、冲突与无效条目；不默认静默覆盖用户修改。校验版本、必填内容、标识冲突和引用关系；失败时保留现有数据。自定义文本按内容展示，不作为可执行脚本导入。

提供三种导出：

1. 内容包：作品、作者、分类、模块及来源，用于维护和分享。
2. 个人备份：配置、收藏、学习记录及本地内容修改，用于恢复或迁移。
3. 学习 HTML：包含当前选定内容与配置的可独立打开文件；默认不包含个人学习记录。

保存设置不等于改写原始 HTML 文件。页面应明确区分“保存在本机浏览器”和“导出到文件”。备份应带格式与内容版本，作品更新时尽可能保留稳定标识和学习记录。

## 9. 单文件交付与设备边界

最终交付一个内置样式、交互脚本和学习内容的 HTML。核心目录、搜索、详情和练习可离线使用，不依赖外部接口、字体或 CDN。

项目内部可将内容、配置和界面分开维护，再生成一个交付文件。用户拿到的文件不需要安装开发环境，也不需要启动本地服务。

学习记录和设置优先保存在当前浏览器；需要检测存储能力，保存失败时明确提示并提供导出。不同设备不自动同步，换文件名、路径、浏览器或清理数据可能影响本地记录，备份导入承担迁移职责。

手机端需要区分“浏览器页面”和“聊天工具或系统文件预览器”。后者不一定运行 HTML 交互脚本，不能承诺任意预览入口都可使用。交付验收应实际验证约定的 Android 与 iOS 打开方式；必要时可将同一个 HTML 放到静态地址访问，托管属于单独确认的分发方式。

音频会明显增大单文件体积；系统朗读的古诗文读音也不一定准确，首版先做好文字与朗读提示，音频作为后续选项。

## 10. 分阶段交付建议

| 阶段 | 产出 | 完成条件 |
| --- | --- | --- |
| 当前：方案确认 | 本讨论稿，明确范围、分类、内容模块、卡片交互与配置方式 | 用户确认或提出修改，形成实施基线 |
| 内容底座与样例 | 经核对的目录框架、来源字段、分类词表、约 12–18 篇代表性完整内容 | 覆盖小学、初中、高中及诗词曲古文等不同形态，验证节选、同题、异文与多标签规则 |
| 首版学习文件 | 含代表性内容的完整学习闭环，支持搜索分类、详情、理解与背诵、进度、配置、备份和导出 | 手机与电脑可完成一轮学习并保存、导出和恢复记录 |
| 完整内容交付 | 扩充到约定教材与课程范围，补齐详解，再加入经过审核的拓展作品 | 核定目录全部有详情；内容覆盖与来源审校达到要求；输出完整单文件 HTML |
| 后续增强 | 比较阅读、更多专题、可选音频、逐篇编辑等 | 在首版使用反馈和明确需求基础上加入 |

样例阶段用于验证内容组织和学习体验，不替代最终全量目录和详解的交付。正文、译注与讲解的校核通常比页面编写更耗时，实际数量和工期应在目录范围核定后估算。

首版必做：教材和课程范围映射、拓展标识、多级多标签、全文检索、作品详情模块、理解与背诵卡片、复习和收藏、响应式布局、分类和模块配置、导入导出及离线交付。

后续可加：两篇以上的比较阅读、作者生平时间轴、精细化拼音切换、音频朗读、连续学习统计、专门的考试专题。首版不以账号系统或联网服务作为前提。

## 11. 验收标准

### 内容

- 核定范围中的每个教材条目都有明确收录位置、版次和详情入口；全部必需详情模块有内容或明确的不适用说明。
- 背诵要求有来源，并精确到全文或段落；拓展推荐不会被显示成全国统一必背要求。
- 同一作品重复收录不重复维护主体；同名不同作品可正确区分；节选和原文版本可追溯。
- 标签与原文、分析有对应依据，不把朝代、作者风格和文学流派混为一类。
- 来源、注音、译注、背景、手法与思想均经过内容复核；争议和不确定信息有标注。

### 使用体验与配置

- 用户可从教材目录或主题分类进入作品，完成阅读、练习、自评、再次复习的闭环。
- 学生能清楚区分理解掌握和背诵掌握；家长可调整模块显示和学习范围。
- 手机、平板与电脑可完成主要操作；窄屏和字号放大时不出现正文或按钮被截断。
- 新增分类、移动层级、调整模块或导入作品后，目录、筛选和详情同步生效。
- 断网仍可使用核心功能；备份导出后能恢复设置和进度；存储不可用时能继续学习并获取提示。
- 内容更新不会无提示地覆盖个人配置或错误地继承已变更文本的背诵状态。

### 样例评审任务

用代表性样例实际验证：按教材找一篇作品、按“情感 + 景物”交叉检索、从原句查看注释、遮盖指定段落背诵、撤销一次误标、添加一个分类、停用一个模块、导出并恢复一次备份。这些任务通过后再全面铺开内容，避免全量制作后返工。

## 12. 待本轮方案确认的设计建议

1. 采用“教材目录 + 多维多级分类”的并列入口，一篇作品可从多个入口访问。
2. 采用“作品阅读卡 + 理解练习卡 + 背诵练习卡”，用同一份内容支撑不同学习方式。
3. 内容模块按学段提供预设，支持用户增减、排序和扩展。
4. 使用轻量页面配置与内容包维护，交付离线单文件 HTML，并提供明确的备份及导出能力。
5. 先用代表性内容验证规则与体验，最终交付仍覆盖核定范围的完整目录与详情。

确认后再开始资料全面核查、样例内容制作和 HTML 实现；本文件中的阶段划分与默认交互均为可讨论方案。
